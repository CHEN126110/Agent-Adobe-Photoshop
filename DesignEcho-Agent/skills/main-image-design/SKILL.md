# 主图生产工作法

主图不是一个固定版式，而是一套**按规格组织的生产容器**。点击图负责争取注意与商品识别，转化图负责承接可信购买理由；具体做几张、每张承担什么任务，必须由当前 Agent /用户根据商品和目标决定。深度设计方法论用 `getMainImageDesignFramework` 检索；本手册只讲店铺的生产组织与结构 ground truth。

## 店铺生产体系（来自真实生产文件）

- **按规格分文档**：`800` 工作画布 1500×1500（1:1），`750` 工作画布 1500×2000（3:4），`1200` 工作画布 1440×2160（2:3）；三者均为 72 ppi、RGB/8。`PSD/{规格}.psb` 是当前项目的可编辑交付约定；用户提供的批量脚本只证明 raster 导出，不证明源文件扩展名。
- **固定空骨架**：每个文档都有顶层「转化图」和「点击图」父组、一个锁定白色「背景」层。点击图包含 5 个空槽 `{规格}-1`～`{规格}-5`；转化图包含 4 个空槽 `2`～`5`。这些是容量和命名，不代表必须填满，也不表示 5 个点击槽一定是备选版本。
- **面板顺序**：从上到下是转化图 `5→2`、点击图 `{规格}-5→{规格}-1`、背景。创建顺序只是 Photoshop 实现细节，执行后必须读回真实层级，不能靠数组顺序猜。
- **内容 assignment**：Agent /用户决定本次填哪些槽、每槽使用哪些素材、表达什么目标以及采用什么构图。空槽只保留结构，不执行置入、变换或导出；多个已分配方向不能由 Harness 把一个全局素材自动复制到每槽。
- **导出规则**：批量脚本对 800/750/1200 都处理「转化图」「点击图」，仅导出结构非空的子组；JPEG 名等于子组名，目录为 `主图/{规格}`。导出保持完整工作画布，并在每次导出前隔离兄弟子组，不能裁紧内容后拉伸，也不能叠加其它方案。
- **尺寸证据边界**：当前脚本不做 resize，因此只能确认按工作画布导出；它不能证明最终平台上传必须是 800×800、750×1000 或其它尺寸。平台上传尺寸在取得后台/用户明确规范前保持未知。

## 点击图的内容结构边界

点击图没有默认图层数、主素材角色、文字数量、版式或组件组合。纯摄影、平铺重组、细节证明、变体比较、图文构成或其它方向都可能成立；它们只是 Agent 可以比较的表达方式，不是 Skill 提供的候选答案。

每个进入画面的对象都必须服务当前点击目标：提高商品识别、形成与商品相关的注意力、表达可信利益点，或建立必要的品牌 /渠道关系。摄影自身的光影和质感、受控后期处理、文字与图形都只是可用手段；不能因为历史项目曾使用某种结构，就把它复制为当前任务的默认方案。

场景、穿着、平铺、细节、包装和变体素材没有全局优先级。联系表只扩大观察覆盖，G 编号、文件顺序、目录名和历史样本不表示推荐名次；Agent 必须查看当前像素，并结合商品、点击目标、裁切空间和信息责任显式选定主视觉与辅助关系。吊牌、背景杂物等是需要观察和处理的事实，也不能在未看图时直接判定整张素材不可用。

## 开放创意的两段式生产

普通创意主图不要把一张素材和一个矩形 placement 一次性提交给 Skill 后就当成设计完成。使用下面的职责分工：

1. Agent 先根据当前项目证据明确选择一个工作规格，调用 `main-image-design`，设置 `mainImageProductionAction=prepare`。Skill 只创建该规格的白色工作文档与标准空组，并返回 `mainImageWorkspaceRef`、真实 documentId、group layerId 和准备完成时的 Photoshop 历史版本；此时没有保存、导出或设计成稿。
2. 控制权立即回到同一个 Agent。Agent 继续看素材和画面，使用通用 Photoshop 工具完成多素材组合、裁切、缩放、文字、形状、蒙版、层级和视觉平衡。需要哪些元素、放多大、是否用文字、采用什么版式，全部由 Agent 决定；Skill 不提供固定图层数或视觉答案。
3. 至少一个标准子组已经有真实设计内容后，Agent 使用 prepare 返回的同一个 `mainImageWorkspaceRef` 调用 `mainImageProductionAction=finalize`。Skill 只读回同一 TaskRun、同一文档、同一组身份和新 Photoshop revision，导出真实非空组，并把可编辑稿与 raster 作为完整文件事务提交。
4. 文件收据闭合后仍要由 Agent 查看真实导出图并判断视觉质量。finalize 成功只证明文件、路径、图层组和 Photoshop 版本一致，不证明画面已经好看。

workspace 引用只是任务身份，不是权限。换 TaskRun、换项目、文档或组被替换、prepare 后没有发生设计变化、标准组仍为空、已经成功 finalize 后重复提交，都会在保存和导出前停止。若用户只是明确要求一个空骨架文件，仍使用 `createEmptySkeleton=true` 的确定性交付；不要把它与开放创意 prepare 混为一谈。

## 需要完成的设计判断（顺序由 Agent 决定）

- **认料与方向**：联系表用于扩大候选覆盖，不直接选赢家；产品事实、材质和卖点必须有来源。只有具体的构图、气质或表达问题仍不确定时，才观察 Eagle 参考来回答该问题。
- **主视觉判断**：把真正有机会的候选放大观察，比较商品识别、主体姿态、光影、质感、裁切空间和使用场景，再由 Agent 选定主视觉。
- **信息表达按需**：只有可信且对点击目标必要的信息才进入画面。若需要文字，建立清楚的主次层级；若摄影已经完成任务，无文字方案同样是成品。
- **元素必要性**：每个辅助图、角标、装饰或文字都要在真实缩略图中增加产品识别、点击理由或可信证据。没有增加就删除；不要只在错误元素上继续缩放、移动或叠加效果。
- **成稿复核**：同时看正常尺寸和平台缩略图。发现问题时比较保留微调、删除、替换和换方向，选择副作用最小但能解决根因的方案，而不是默认沿着首稿继续修补。

## 沿用用户的交付习惯

开始建立输出文档和文件名之前，先从当前项目里挑少量与本任务同类的**既有设计成品**作为组织方式参考；不要把摄影原图目录、临时目录或无关品类目录当成规范。用项目结构与资源搜索确认候选，再对代表性的 PSD / PSB 做结构读取，提炼候选习惯：规格怎样分目录或分文档、版本怎样编号、可编辑稿与导出图怎样配对、图层组怎样命名。

这些观察是证据，不是 Harness 预设。采用顺序是：用户当前明确要求 > 已确认的项目交付规则 > 当前项目中重复出现且与本任务匹配的做法 > 本手册示例。由 Agent 判断哪些习惯适合当前交付；确定性代码只校验路径安全、名称可用、文件不冲突和交付集合完整。选定后可用 `updateDesignProjectState` 提议一条 `delivery` 规则并附代表文件引用，后续复用；只有一个孤例时标为候选，不冒充用户标准。

## 查实的事实要落地

规格体系、已有变体版本号、选定的主视觉——用 `updateDesignProjectState` 记下，下轮免重查。
