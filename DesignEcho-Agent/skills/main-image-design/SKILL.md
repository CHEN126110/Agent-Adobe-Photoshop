# 主图生产工作法

主图不是一张图，是一个**按规格组织的体系**：点击图（首图，决定点击率）+ 转化图（第 2-5 张主图位，承接说服）。深度设计方法论用 `getMainImageDesignFramework` 检索；本手册讲店铺的生产组织与结构 ground truth。

## 店铺生产体系（来自真实生产文件）

- **按规格分文档**：`800.psb`（1500×1500，2 倍稿出 800×800）、`750.psb`（1500×2000，2 倍稿出 750×1000）、`1200.psb`（1440×2160 一类竖版）——一个文档管一个规格的全套主图。
- **文档内组织**：顶层「点击图」组 + 「转化图」组。点击图内 `{规格}-{序号}` 变体组（如 800-1 … 800-5）——**5 个备选版本，只显示当前选用的一版**；转化图内按主图位序号 2/3/4/5 分组。
- 交付 = 在对应规格文档的对应组里工作；新方案新开一个变体组，不覆盖旧版本。

## 点击图样板中的精简分层（不是固定配方）

真实项目里有一类点击图变体组只用了 4 层：

```
摄影主视觉 <智能对象>     ← 一张好照片是画面的全部底子
材质/核心词 <大字文字>    ← 如「桑蚕丝」
卖点句 <文字>             ← 如「柔润亲肤·无骨缝头」
复用组件 <智能对象>       ← 跨规格共用的角标/组件
```

这 4 层是样板证据，不是每稿都要填满的模板。摄影已经同时承担商品识别、点击理由和气质时，一张摄影智能对象经过准确裁切就可以是完整点击图；没有可靠文案或必要组件时不要为了“显得设计过”而补齐图层。

结构越少越好：光影、质感、氛围优先来自**摄影本身**，不靠效果堆叠。选主视觉是第一决定——用联系表形成候选，真看图后根据当前商品与点击目标判断；“场景/穿着优先、带吊牌原始素材慎作首图”是常见经验，不是替代视觉判断的排序规则。

## 需要完成的设计判断（顺序由 Agent 决定）

- **认料与方向**：联系表用于扩大候选覆盖，不直接选赢家；产品事实、材质和卖点必须有来源。只有具体的构图、气质或表达问题仍不确定时，才观察 Eagle 参考来回答该问题。
- **主视觉判断**：把真正有机会的候选放大观察，比较商品识别、主体姿态、光影、质感、裁切空间和使用场景，再由 Agent 选定主视觉。
- **信息表达按需**：只有可信且对点击目标必要的信息才进入画面。若需要文字，建立清楚的主次层级；若摄影已经完成任务，无文字方案同样是成品。
- **元素必要性**：每个辅助图、角标、装饰或文字都要在真实缩略图中增加产品识别、点击理由或可信证据。没有增加就删除；不要只在错误元素上继续缩放、移动或叠加效果。
- **成稿复核**：同时看正常尺寸和平台缩略图。发现问题时比较保留微调、删除、替换和换方向，选择副作用最小但能解决根因的方案，而不是默认沿着首稿继续修补。

## 沿用用户的交付习惯

开始建立输出文档和文件名之前，先从当前项目里挑少量与本任务同类的**既有设计成品**作为组织方式参考；不要把摄影原图目录、临时目录或无关品类目录当成规范。用项目结构与资源搜索确认候选，再对代表性的 PSD / PSB 做结构读取，提炼候选习惯：规格怎样分目录或分文档、版本怎样编号、可编辑稿与导出图怎样配对、图层组怎样命名。

这些观察是证据，不是 Harness 预设。采用顺序是：用户当前明确要求 > 已确认的项目交付规则 > 当前项目中重复出现且与本任务匹配的做法 > 本手册示例。由 Agent 判断哪些习惯适合当前交付；确定性代码只校验路径安全、名称可用、文件不冲突和交付集合完整。选定后可用 `updateDesignProjectState` 提议一条 `delivery` 规则并附代表文件引用，后续复用；只有一个孤例时标为候选，不冒充用户标准。

## 查实的事实要落地

规格体系、已有变体版本号、选定的主视觉——用 `updateDesignProjectState` 记下，下轮免重查。
