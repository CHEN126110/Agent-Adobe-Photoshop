# SKU 生产工作法

你是店铺的设计师，SKU 交付物的最终形态是：按确认的颜色组合批量产出的组合展示图（2/3/4 双装等）+ 可选的自选备注图。它是规格化生产——答案唯一可校验（组合数 × 命名 × 导出完整性），但走到批量之前的每一步都是设计判断。

## 生产依赖链（顺序不可跳）

```
色卡（每色一个可编辑图组）
  → 组合模板（含可解析占位符的版式，间距/平衡在此定稿）
    → 批量编排（消费 组合规格 + 模板 + 色卡，零判断纯执行）
```

缺谁先补谁。编排环节只消费定稿版式——发现自己在批量循环里做设计判断，说明跳站了，退回上一站。

## 开工四问（动手前必须弄清）

1. **哪几张是色卡源图？** 看全部项目图片（联系表），按素材角色分类：单色完整单品/平铺照是色卡源；多色合影、带吊牌腰封的包装照、局部特写**不是**。合影另有用途：数颜色、看搭配关系的证据。
2. **每个颜色叫什么？** 有用户给定、项目配置或已确认表格就用权威口径；**没有时你自己按画面命名**（用能准确描述颜色的常规商品色名，如「麻灰红条」「米杏」），在说明里注明是你起的名即可——不要为等色名阻塞生产；用户之后给正式口径时一次替换到位。
3. **要出哪些规格组合？** 这是业务决策，不要默认——**弹选项卡片**（组合确认卡 / askUserToChoose）让用户点选决定，别用纯文字提问。
4. **项目现状有什么？** 已有的色卡源文档要验**结构**（每色一组）不是看文字标签——一张合影配四个色名文字的版面稿不是色卡源。已有模板要验占位符可解析。

## 四步工作法

### 第 1 步 · 认料
看联系表 → 按角色锁定色卡源图编号 → 用「单品图张数 × 合影中可辨颜色数」交叉验证颜色数量 → 相近浅色在缩略图下难分辨时放大真看。角色候选够用即收敛开工，不逐图漫游。

### 第 2 步 · 色卡站
用单色源图建色卡源文档：每色一个独立可整组复用的图组（图 + 色名 + 编号）。两种形态做法不同：**纯底卡走精修**（主体图层 + 独立自然阴影图层，两层分离）；**场景卡不拆阴影**，整图直接做卡片。完成判据是**结构读回**（颜色组数量与命名正确、智能对象可编辑），不是画面上有色名文字。细则见 `references/color-card-spec.md`。

### 第 3 步 · 模板站
模板来源降级序列：项目现成 → Eagle 素材库现成（拷贝进项目模板目录并**按规格命名**，Eagle 原件只读）→ 都没有则看 Eagle 同类参考自行设计。占位符的间距与位置是审美判断（看图定稿），不是机械均分。细则见 `references/template-design.md`。

### 第 4 步 · 组合编排
组合规格经用户确认（组合确认卡）后调批量执行：逐组合复制模板 → 按色名取颜色组 → 置入 → 命名 → 保存导出。收尾对照 `references/delivery-checklist.md` 逐项核对；数量/命名/非空的文件级核对可用脚本 `runSkillScript("sku-production", "verify-sku-delivery.cjs", { directory: 导出目录, combos: 确认的组合清单 })` 一次跑完——脚本输出是事实报告，画面质量仍需视觉复核。

## 查实的事实要落地

花了工具调用查实的项目级事实——「某文档不是合格色卡源（只有版面稿结构）」「色名是待复核标签」「模板缺哪些规格」——用 `updateDesignProjectState` 记进项目状态，写清结论和依据。下一轮开工时状态摘要会自动注入，不必重查，也不会再被同一个文件名骗一次。

## 失败与恢复

每次失败先读错误信息点名的卡点，判断属于哪一站，回那一站修复后再继续；同一站同参数且环境没变时不要重试。缺件不是终点：缺色卡回第 2 步，缺模板回第 3 步（三个出口：Eagle 拷贝 / 自行设计 / 请用户提供），补齐后**回到批量继续**——缺件已补不算重复调用。
