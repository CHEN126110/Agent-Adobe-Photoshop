# 色卡规范

## 色卡是什么

可靠素材单元，不是组合模板也不是版面稿。它保证每一种真实颜色可识别、可追溯、可替换，是后续一切 SKU 编排的唯一颜色来源。**模板和成品不在色卡源文档上做。**

## 结构底线

- 每个颜色 = 一个独立、可整组复用的图组：该色商品图 + 色名 + 编号为一组。
- 商品图以智能对象置入，受圆角底约束（剪切蒙版），保持可替换。
- 后续编排按组合抽取颜色组时，不需要再裁切、抠选或拆图。
- 同批色卡保持主体尺度、裁切、背景、标签、顺序一致；不要为"丰富画面"给不同颜色不同风格。

## 两种交付形态（结构与做法不同，不只是用途不同）

| 类型 | 用途 | 结构要点 | 制作流程 |
|---|---|---|---|
| 纯底色色卡 | SKU 编排、模板复用 | 每色一组，组内包含透明主体智能对象与色名；主体置于同尺寸透明画布 | 抠出透明主体，保持真实版型，按同批基准等比统一尺度 |
| 场景背景色卡 | 上架展示 | 每色一组，组内**整张卡片封为一个智能对象**（卡内：色名标签 + 圆角标签底 + 场景照剪切进圆角基底） | 不做阴影分离、不走精修 |

> **当前实现阶段（2026-08-25 拍板）**：`prepareSkuRetouchAssets` 只做“透明主体等比缩放到统一尺度”——不变形（保留每只袜子的真实版型）、不产阴影件、不产中性灰。历史样板中的真实投影提取（白场法）与光影修正是后续工序；本阶段验收不要按缺少阴影或光影层报错，也不要宣称这些工序已经完成。

### 真实样板结构（店铺 ground truth，来自生产文件逐层解析）

**纯底卡完整历史样板**（样板 C-1183/PSD/SKU.psb；其阴影与光影结构不属于当前自动化退出条件）：

```
每色一组「色名」：
  ├─ 阴影件 <智能对象>   内部：阴影像素层（+隐藏的主体参考层）
  ├─ 主体件 <智能对象>   内部：形态统一后的袜子主体层
  └─ 色名 <文字>
参考组：Number 1..N 编号文字
```

**场景卡**（样板 C-1248/PSD/SKU.psb）：

```
每色一组「色名」：
  └─ 色名 <智能对象> → 卡片文档（如 800×1216）
        内部：色名<文字> + 标签底<白圆角矩形> + 场景照<智能对象>[剪切] + 卡片基底<黑圆角矩形>
参考组：Number 1..N 编号文字
```

- **复用与替换发生在智能对象内容层**：换色/换图是替换 SO 内的照片或主体，不是重摆图层——这是"可整组复用"的真正实现方式。
- 纯底卡的自然阴影独立成件才能随主体复用、按底色调整浓淡；场景照自带环境光影，拆阴影既做不干净也没意义（精修工具的 sourceMode=auto 会自动跳过场景图）。
- **命名陷阱**：历史样板里智能对象的图层名与内容可能错位（名叫「阴影」的装着主体）。读样板时按**内容**认件，不按图层名猜。

## 源图判据

- **合格**：单色的完整单只照或平铺照。
- **不合格**：多色合影（无法按色抽取）、带吊牌/腰封的包装摄影（是展示图不是颜色展示）、局部特写（不完整）。
- 合影的正确用途：颜色数量与搭配关系的证据——单品图张数与合影中可辨颜色数互相印证；对不上或浅色难辨时放大真看，仍不确定问用户。

## 色名真值

优先级：用户给定 > 项目配置/已确认表格 > 既有图层读取 > **Agent 按画面自命名**。用户没有提供色名时，你有权直接命名（准确描述颜色的常规商品色名），注明来源是自命名、继续生产不阻塞；用户之后给正式口径时全链一次替换（图层组名、标签文字、导出文件名同步）。时间戳、流水号、相机文件名不能当色名。

## 手工工艺参照（店主示范录屏，2026-08-25，21 分钟完整闭环）

用户亲自录制的纯底色卡制作全程，操作顺序就是权威工艺：

1. **认料定色**：在素材目录看全部图 →「可以看出来是 4 个颜色的袜子」→ 选出每色一张单只原图；
2. **原图按色重命名**：把选定源图的文件名改成色名（DSC 相机名 → 色名）——**色名真值从这一步建立**，之后文件名即色名；
3. **建卡 + 画占位矩形**：新建卡文档后先画一个矩形，「这个矩形代表着袜子的边框大小」——**主体在卡内占多大是先行的设计判断**，矩形就是这个判断的落点；
4. **逐色对齐进框**：每色置入原图（含背景摄影图），自由变换 + 参考线把袜子对齐进占位矩形——「这样差不多都在一个大小」，跨色尺度一致靠同一个框保证；
5. **色名标签**：每卡加色名文字（先「名称」占位，定稿改真名）；
6. **一致性校验**：卡底两两对比「这两个是一样大的」——底尺寸与主体尺度都要同；
7. **色准与抠图（动作批量跑，录屏里几乎不留痕）**：转 16 bit → **设置白场**（把摄影灰白背景校到纯白、同时校正整体白平衡）→「B1 纯色抠图」动作逐颜色组批量执行去底；
8. **合排总览**：白底合排 + 顶部编号 1/2/3/4 + 底部色名（奶白/粉色/灰色/咖色）——编号由脚本生成，与生产文件里「参考组 Number 1..N」的命名完全同源。

对 Agent 的映射：步骤 3 的占位矩形 = cardBounds/主体尺度框（先声明设计判断再机械对齐）；步骤 2 说明**规范流程里色名会先进文件名**——遇到相机名源图时，确定色名后应把「文件 ↔ 色名」映射固化下来（写进项目状态），而不是每轮重新猜；步骤 7 说明**色准校正是独立工序**——Agent 的抠图（分割模型）不依赖背景纯度，但白场/白平衡校正不能因此省略，否则色卡的「颜色」本身就是失真的。

### 录屏里看不见的自动化层（动作 + 脚本分工清单）

店主口述「我是跑的脚本和动作」——以下步骤在录屏帧间隙里瞬间完成，逐一对账到脚本目录：

| 工序 | 载体 | 关键参数 |
|---|---|---|
| 设置白场 | 动作「阴影背景调整」：色阶 + 白场吸管（截图实证） | 作用对象是**阴影件内部的背景图层**：直方图整体堆在高光端，白场吸管把带影子的灰白背景推成纯白、影子保留——既是背景纯白化也是白平衡校正 |
| 抠图 | 动作「B-01 矩形选区抠图」「B1 纯色抠图」（动作组「脚本」）+ `动作播放.jsx` 驱动 | 逐颜色组选中、每组执行一次，图层组优先、无组则按智能对象遍历 |
| 16 bit 前置 | `16Bit.jsx` 同目录脚本 | 8→16 bit/channel，调整前转换防色阶断层 |
| 编号参考组 | `创建数字参考2.0.jsx` | 遍历顶层颜色组建「参考组」，每组水平居中、垂直中心上移组高 8%，100pt 文字「Number i」——生产 PSB 参考组的直接出处 |
| 形状参考框 | `创建参考矩形.jsx` | 按选中组 bounds 生成 10px 圆角矩形「形状参考」 |
| 精修光影（对照方案） | `曲线/Luminosity_DB_Setup.jsx` | 明度锁定 D&B：压暗曲线 128→90 / 提亮曲线 128→170，混合模式=明度（防色偏），反向蒙版起手——与中性灰柔光方案目标相同、实现不同 |

动作面板截图实证的完整工序编号链（2026-08-25）：`B-01 矩形选区抠图 → B1 纯色抠图 → 阴影背景调整 → C1 组修改文字 → C-2 修改所有字体 → D1 SKU-颜色排列 → D1-2 图层组序号 → E1 写入颜色配置 → F1 保存到新建文件夹`——B=抠图与背景、C=文字、D=排列与编号、E=配置写入、F=归档，工序字母即生产顺序。

分工规律与本手册的架构裁决同构：**判断（认色、选图、命名、定尺度、对齐、校验）全部人做；确定性几何与像素处理（白场、抠图、编号、排列）全部动作/脚本做**。脚本从不认色、从不选图。

## 合排算法参数（店铺脚本 ground truth，桌面「脚本」目录 .jsx）

四色合排总览的确定性算法（`颜色组排列.jsx`，与视频合排步骤对应）：

1. 排除「参考组」与空组；
2. **等高归一**：全部颜色组缩放到最高组的高度（锚点居中）——跨色主体尺度一致的代码实现；
3. 组间距 = 画布宽 **2%**；左右边距 = 画布宽 **5%**（各一侧）；
4. 整体缩放到画布宽的 90% 后，实测宽度均分间距、水平居中。

竖排版（`色卡排版.jsx`，复制到详情页用）：每 3 组合一行、组间距 = 组高 **10%**、整体缩放到画布高并居中。这些百分比是店铺的排版 token，做同类排列先用它们，再按画面微调。

## 验收（看结构不看标签）

- 颜色组数量与颜色数一致，组名是色名（不是「图片」「文案」「色卡」这类结构名）。
- 主体没有拉伸、关键部位没被裁掉、同批尺度一致。
- 标签在目标尺寸下可读；智能对象仍可编辑；保存读回后颜色资产完整。
- **反例警示**：一张合影 + 四个色名文字标签的版面稿，画面上看似"色卡"，结构上没有任何颜色组——它不是色卡源文档。
- **反例第二变体（2026-08-25 真机抓获，Agent 自产）**：四张单色图 + 色名文字，但顶层按**内容类型**分组（一个「图片」组 + 一个「文案」组）——画面同样"像色卡"，结构上抽任何一色都要跨两个组翻找，无法整组复用。分组轴必须是**颜色**，不是内容类型。产出色卡后自验第一问：随便挑一个色，能不能整组拖走？
