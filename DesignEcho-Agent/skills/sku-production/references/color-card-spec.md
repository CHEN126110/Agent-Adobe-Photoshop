# 色卡规范

## 色卡是什么

可靠素材单元，不是组合模板也不是版面稿。它保证每一种真实颜色可识别、可追溯、可替换，是后续一切 SKU 编排的唯一颜色来源。**模板和成品不在色卡源文档上做。**

## 结构底线

- 每个颜色 = 一个独立、可整组复用的图组：该色商品图 + 色名 + 编号为一组。
- 商品图以智能对象置入，受圆角底约束（剪切蒙版），保持可替换。
- 后续编排按组合抽取颜色组时，不需要再裁切、抠选或拆图。
- 同批色卡保持主体尺度、裁切、背景、标签、顺序一致；不要为"丰富画面"给不同颜色不同风格。

## 两种交付形态（结构与做法不同，不只是用途不同）

| 类型 | 用途 | 结构要点 | 制作流程 |
|---|---|---|---|
| 纯底色色卡 | SKU 编排、模板复用 | 每色一组，组内**主体件与阴影件各封为独立智能对象** | 需要精修：形态统一主体、抽出袜子的自然投影为独立阴影件、中性灰光影修正——这正是 prepareSkuRetouchAssets 生成的资产 |
| 场景背景色卡 | 上架展示 | 每色一组，组内**整张卡片封为一个智能对象**（卡内：色名标签 + 圆角标签底 + 场景照剪切进圆角基底） | 不做阴影分离、不走精修 |

### 真实样板结构（店铺 ground truth，来自生产文件逐层解析）

**纯底卡**（样板 C-1183/PSD/SKU.psb）：

```
每色一组「色名」：
  ├─ 阴影件 <智能对象>   内部：阴影像素层（+隐藏的主体参考层）
  ├─ 主体件 <智能对象>   内部：形态统一后的袜子主体层
  └─ 色名 <文字>
参考组：Number 1..N 编号文字
```

**场景卡**（样板 C-1248/PSD/SKU.psb）：

```
每色一组「色名」：
  └─ 色名 <智能对象> → 卡片文档（如 800×1216）
        内部：色名<文字> + 标签底<白圆角矩形> + 场景照<智能对象>[剪切] + 卡片基底<黑圆角矩形>
参考组：Number 1..N 编号文字
```

- **复用与替换发生在智能对象内容层**：换色/换图是替换 SO 内的照片或主体，不是重摆图层——这是"可整组复用"的真正实现方式。
- 纯底卡的自然阴影独立成件才能随主体复用、按底色调整浓淡；场景照自带环境光影，拆阴影既做不干净也没意义（精修工具的 sourceMode=auto 会自动跳过场景图）。
- **命名陷阱**：历史样板里智能对象的图层名与内容可能错位（名叫「阴影」的装着主体）。读样板时按**内容**认件，不按图层名猜。

## 源图判据

- **合格**：单色的完整单只照或平铺照。
- **不合格**：多色合影（无法按色抽取）、带吊牌/腰封的包装摄影（是展示图不是颜色展示）、局部特写（不完整）。
- 合影的正确用途：颜色数量与搭配关系的证据——单品图张数与合影中可辨颜色数互相印证；对不上或浅色难辨时放大真看，仍不确定问用户。

## 色名真值

优先级：用户给定 > 项目配置/已确认表格 > 既有图层读取 > **Agent 按画面自命名**。用户没有提供色名时，你有权直接命名（准确描述颜色的常规商品色名），注明来源是自命名、继续生产不阻塞；用户之后给正式口径时全链一次替换（图层组名、标签文字、导出文件名同步）。时间戳、流水号、相机文件名不能当色名。

## 验收（看结构不看标签）

- 颜色组数量与颜色数一致，组名是色名（不是「图片」「文案」「色卡」这类结构名）。
- 主体没有拉伸、关键部位没被裁掉、同批尺度一致。
- 标签在目标尺寸下可读；智能对象仍可编辑；保存读回后颜色资产完整。
- **反例警示**：一张合影 + 四个色名文字标签的版面稿，画面上看似"色卡"，结构上没有任何颜色组——它不是色卡源文档。
