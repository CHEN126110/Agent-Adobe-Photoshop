## 0. 一句话

**当前采用的边界是：七步工作法属于 Design Kernel 的可选认知脚手架；Harness 提供上下文、能力、执行和验证基础设施，但不把七步固化成每次任务的阶段机。** 下文“七步 × 四层”只作为问题分类法保留，不再是生产运行顺序。

目标不是让 Agent 变成主图机器，而是让它成为一位**不分品类、稳定不犯低级错、能自助完成**的设计师；品类知识住数据层，规格化生产住 Skill，Agent 自选。

## 1. 现状与诊断（真机，非推测）

- 08-14~08-17 共 41 次真实运行：0 次自然完成；59 次工具失败里约三分之二是 Harness 拒绝模型（简报表单驳回 15、状态新鲜度门禁 14、观察预算 6、写保护 5）。全窗口 469 次运行「完成且真有写入」4%。
- 同一项目同一下午：绑 Stage 机的三次「帮我做详情页」零写入；未绑的一次续跑写入 6 层。**病根在权限层，不在模型**（模型对画面的判断原话是对的）。
- 08-17 拆掉写入门禁后，主图任务首次自然完成写入；随后暴露的是**设计层**问题：没看产品图就抄旧稿文案（「防滑硅胶」）、文字压主体、文字层不知放哪、字号靠感觉、29 次观察对 6 次写入、把一张 png 当成主图文档、看图额度耗尽后失明。
- 已做的分诊（均已 build，`runtime_integrated`，真机复测中）：创意清单 `execution_model:'agentic'` 退出 Stage 门禁；观察预算改提醒；proven-applied 写入不锁；表单驳回可执行 + 上撞墙账本；预算抬到设计工作量级；缩略图降级不失明；模型回合可见并计秒；「这次怎么做」可见；产品事实先于文案；文档性质判断；Agent 自主版面声明 + 主体感知几何执行；`getSubjectBounds` 进手边；棘轮扩容 + 宪法入 CLAUDE.md/AGENTS.md。2026-08-21 已删除曾经落地的 6 套内置版式配方。

**结论**：分诊有效但属于「症状层」。要不再打地鼠，需要一个能给每个症状定位的骨架，并在骨架上做通用修。

## 2. 核心主张：七步工作法 × 四层支撑

### 2.1 七步（通用，不分品类）

| 步 | 设计师在想什么 | 做好的标志 |
|---|---|---|
| ① 目的 | 给谁看、什么场景、要对方做什么决定 | 一句话说得出这张图的任务 |
| ② 内容 | 一个主张 + 几条支撑事实；哪些是真的、来源在哪 | 主张单一、事实可查、不编 |
| ③ 材料 | 有什么素材、缺什么；哪张主体清楚、有留白；这个文件是画布还是素材 | 选对图、认清文件性质 |
| ④ 结构 | 信息层级 → 版式骨架（主体 / 标题 / 证据各在哪） | 主体大而清、文字住留白、一格一元素 |
| ⑤ 视觉语言 | 一底一强调、字体气质、与产品与品牌一致 | 干净、有主次、像同一家 |
| ⑥ 制作 | 比例、对齐、间距、字距、图层组织 | 数值合规范、结构可编辑 |
| ⑦ 看与修 | 眯眼看层级、细看可读性、对照 ①；只修最影响的 1–2 处然后停 | 改完更好而不是不同 |

三根支柱撑着判断：**参考**（好的长什么样）、**规范**（这家店 / 这个平台的数字）、**反馈**（做完被留下还是被打回）。

### 2.2 每步四层

- **知识**：设计师这一步怎么想（通用原则 + 按任务类型取用的品类知识）。
- **引擎**：这一步里确定性的部分自动做（坐标、层序、建组、避让、比例、对比度），模型不徒手。
- **证据**：这一步动手前该看过什么（默认习惯：提醒不拦截；缺失在事后验收暴露）。
- **验收**：这一步做完什么算过——**量的量、看的看**；只有「有唯一正确答案」的项可硬（事实、几何），其余是提示。

### 2.3 与既有约束的关系

- 与「设计路径宪法」一致：本方案不新增任何前置拦截；所有「证据」是提醒，所有「验收」是事后。
- 与「Agent 是设计师不是品类机器」一致：七步与四层只用构图角色 / 结构事实措辞；品类内容只以知识条目和 Skill 形式存在。
- 与「确定性归代码、创造性归模型」一致：引擎层只接管有唯一正确答案的部分。

## 5. 可行性

**技术**
- 承载模块大部分已存在（表 3 中「已」项）；新增以数据与循环外模块为主，不改主循环结构。
- 作者权边界由 `test:design-authorship-boundary` 与 `test:compose-design-spec` 覆盖；内置配方测试已随配方实现退役，真机设计效果仍需重载后复验。
- 模型能力假设：主力 mimo / deepseek（走 OpenAI 适配），文字判断中等、看图中等偏弱、带图回合 40–110 秒。方案对此的应对是**把确定性做进引擎、把提醒放进工具结果**，不依赖模型「记住并遵守」提示；换更强模型收益叠加。
- Eagle：本机 API 与库路径可直接读，文件夹树 / 标签即分类法；不依赖 MCP 在线也能出「地图」。
- Photoshop / UXP：所需原子能力（建组、移层、置入、缩放、文字、主体检测）均已存在。

**数据**
- 参考：Eagle 2519 项、结构完整；配方第一批已由此提炼。
- 规范：项目 / 店铺已有成稿 PSD/PSB；离线解析秒级。
- 事实：Eagle「卖点需求收集」+ 项目产品资料 + 素材观察；缺则问用户一次。

**组织**
- Claude 与 Codex 共用 CLAUDE.md / AGENTS.md 宪法与棘轮；本文为 C 层引用，避免第二套指挥链。

**成本 / 时间**
- P0 一周内可完成（知识 + 原则重排）；P1 以 P0 为坐标系逐项落地；P2 依赖 Eagle 与成稿数据管道。
- 每张单画面目标 ≤ 20 次调用、≤ 3 次带图回合，比现状（30+ 次、5+ 次带图）成本明显下降。

## 6. 预期效果

**定量**（以 08-14~17 为基线）
- 完成且有写入率：4% → 两位数（P1）→ 主要任务多数自然完成（P2）。
- 门禁拒绝占失败比：约 2/3 → < 30%（P0/P1）。
- 单张画面：调用 ≤ 20 次、带图回合 ≤ 3 次、首次写入延迟从 4–5 分钟降到 1–2 分钟。
- 质量硬项：文案无来源功能词 = 0；文字压主体 = 0；图层未分组 = 0；评分卡覆盖 100%。

**定性**
- 单张画面首稿达到参考图的结构水平：标题住留白、一个证据模块、字不压主体、分组可编辑。
- 同店多张图数值一致（P2 后），开始「像你」。
- 上限如实：稳、准、快、像；「一眼惊艳」仍由人拍板。

## 7. 会不会产生新问题 / 再次打地鼠

| 风险 | 表现 | 机制性对策（不是再写一条规则） |
|---|---|---|
| 引擎僵化 | 配方束缚创意，画面千篇一律 | 配方是数据可增；模型可覆盖占比 / 颜色；regions 自由模式保留；成稿→标准让配方数值变成你的 |
| 配方偏见 | 我定的比例不是你的审美 | 每套配方标 provenance；P2 标准覆盖；保留 / 重做即样本 |
| 提示膨胀 | 原则越加越多，反而稀释、互相打架 | P0 按七步重排，每步 ≤3 条；把「原则条数」纳入棘轮只减不增；能做进引擎的不写成提示 |
| 验收误伤 | 硬项拦错正当创意 | 只硬两类：事实（功能词 vs 观察）与几何（越界 / 压主体）；其余提示；新增硬项须有真机档案编号 |
| 模型不遵守 | mimo 无视提示（已发生两次） | 提醒放进工具结果对象；确定性做进引擎；不靠遵守 |
| 眼睛成本 | 看图慢、额度耗尽 | 缩略图降级 + 按需大图 + 写后自读一次；不再失明 |
| 上下文膨胀 | 长任务遗忘、成本平方 | 模型窗口统一预算；系统提示稳定利于缓存；工具面通过只读搜索和精确请求渐进装载 |
| 双 AI 反向 | 一个拆墙一个砌墙 | 宪法 + 棘轮 + 本文 C 层引用；新增拦截三问 |
| 打地鼠回潮 | 又开始按症状加规则 | **判定规则**：任何修复必须标「第几步·哪一层·通用否」；同层同步症状连续两次即升级为骨架项，不许第三次补丁 |

## 8. 不做什么

- 不恢复任何写入前置门禁；不为品类在 Agent 内加分支；不再往 `agent.ts` 长分支；不用 smoke 假绿当验收；不承诺「一眼惊艳」。

## 9. 历史开放问题（已由 2026-08-21 工程裁决关闭）

1. 七步不再完整常驻，每次只装载任务需要的部分。
2. 可证明的产品事实 / 安全错误可阻断；审美与未知能力不作前置硬门禁。
3. 成稿、参考和模型总结都先是有来源候选；是否成为跨任务标准由发布器的人审 /离线评测决定，不从文件是否存在自动推断。

## 附：术语

- **agentic / staged**：manifest 的执行模型；创意路径 agentic（不建 Stage 机），规格化生产 staged。
- **配方（recipe）**：按构图角色定义的版面数据，引擎展开成区域 + 样式一次渲染。
- **硬项 / 提示**：验收里有唯一正确答案的项可要求改（硬项）；其余只列「改哪里」。
