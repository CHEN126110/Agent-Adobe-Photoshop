## 一、需求拆解

用户原话：「Agent 具有蒸馏的能力——信息蒸馏为自己可复用学习的知识沉淀到知识库中，
比如 Eagle 内全部素材文件以及设计师设计的 PSD/PSB，这样 Agent 的设计知识不是死的，
而是可以获取最新的相关参考和知识。」

### 1.1 四个必须都成立的环节

缺一环整条链就是死的：

1. **读**：能把素材/源文件读成结构化数据
2. **炼**：能从中提炼出跨文件复用的规律（而不是逐文件的流水账）
3. **存**：能沉淀到一个持久、可增长、可人工审阅的地方
4. **召回**：设计时能被检索到并真的进入模型上下文

### 1.2 什么是蒸馏：定义与检验标准

蒸馏的本义是加热混合物，让想要的组分先汽化再冷凝收集。三个特征缺一不可：

1. **减量**——产物比原料小几个数量级
2. **丢弃**——大部分原料变成残渣被丢掉，而且要**丢得对**
3. **保留可用性**——提纯后还能干原来的事（蒸出来的酒还得能喝）

**蒸馏 ≠ 索引。** 把 1025 份 PSD 解析后存进库里等检索，那是建索引——原料一份没丢。
蒸馏的产物应该少到可以常驻上下文：**丢掉原料后还能照着做。**

#### 三个深度层次

用字号举例，同一批数据可以停在三个完全不同的深度：

| 层次 | 产物 | 可迁移性 |
|---|---|---|
| **① 事实浓缩** | 「详情页正文 59px，出现 405 次」 | ❌ 换个画布宽度就废了 |
| **② 关系提取** | 「正文 ≈ 画布宽 4.1%，标题是正文的 2.2 倍」 | ✅ 1000px 宽的详情页自动推出 41px |
| **③ 做法还原** | 「这店详情页走高对比层级——标题抓眼、正文补充，所以字号跨度大」 | ✅ 换品类也成立 |

**数值绑死在原始画布上，关系才能迁移。** 本店语料里这一点有直接证据：
SKU 画布 4480x6720、详情页 1440x29999、主图 1500x2000，三个品类画布差十几倍。
统计原始数值会把同一条规律拆成三条互相矛盾的「规范」（SKU 417px vs 详情页 59px），
归一成占宽比例后才看得见它们可能本就是一条。

#### 更高价值的原料：决策的残留证据

PSD 里最值钱的不是参数，是**设计师怎么想的**在结构里的残留：图层组命名、组的嵌套顺序、
蒙版关系。§3.3 的抽样里已经露头——详情页「图片×166 文案×166」完全等量出现，
说明这店的详情页是严格的「一图配一文」结构。这类结构规律比字号高一个量级，
但初版只把它当命名统计，没当结构规律去还原。

#### 检验标准：一页纸测试

> **能不能用一页纸说清「这个店怎么做设计」，并且把 665GB 原料全删掉之后，
> 照着这页纸还能做出符合这店风格的图？**

能，就是蒸馏。不能，只是把文件换了个格式存。

## 三、实测数据（2026-08-19 本机实测，非引用）

### 3.1 语料规模

- **Eagle 库**：2529 条 = 图片 1701 张（jpg 1037 / png 439 / webp 136 / gif 49 / tif 40）
  + **字体 616 个**（ttf 306 / otf 287 / ttc 13 / woff 10）+ jsx 脚本 19 + txt 13
- **单店铺 `D:\A1 neveralone旗舰店`**：**1025 份 PSD/PSB，共 665.1GB**，其中 47 份超 2GiB
  （`fs.readFileSync` 硬边界，真解析不了）

### 3.2 解析成本（8 份真实采样）

```
  76MB 1440x2160  图层 15  | 读盘  633ms  解析  9ms
 218MB 1500x2000  图层 38  | 读盘 1077ms  解析  9ms
 952MB 4480x6720  图层 28  | 读盘 4761ms  解析  6ms
1204MB  790x14742 图层 132 | 读盘 6111ms  解析 34ms
```

**解析恒定 2–36ms，与文件体积无关、只跟图层数走**；瓶颈全在读盘（约 120–200MB/s）。
推算全量 665GB ≈ **55–90 分钟一轮，零模型调用成本**。

对比 Eagle 图像蒸馏：按记忆档案中 08-19 实测的视觉侧调用 60–80s/张，
1701 张 ≈ **28–38 小时**。同一个「蒸馏」需求，两条通道成本差四个数量级。

### 3.3 知识密度验证（56 份文件 / 5374 图层 / 1738 文字层）

按文件名分层抽样后跨文件聚合，验证提炼出的是「规范」还是「噪音」：

| 品类 | 画布 | 字号 Top8 覆盖 | 色板 | 主字体 | 版心左 |
|---|---|---|---|---|---|
| 主图 | 1500x2000 / 1440x2160 | **78%** | 5 种覆盖 100% | MiSans-Demibold ×107 | 5.1% |
| SKU | 4480x6720（9/14 份） | **80%** | **仅 2 种** #000000 / #333230 | AdobeHeitiStd ×62 | 47.8% |
| 详情页 | 1440x29999（9/14 份） | **78%** | 7 种覆盖 100% | MiSans-Demibold ×**692** | 20.2% |

**结论：高度收敛，是真知识。** 几处特别有价值的发现：

1. **字体规范白纸黑字**：详情页 MiSans-Demibold 占 71%、主图占 73%
2. **色板收敛到极致**：SKU 只用两种颜色；品牌绿 #A7CC66 在主图与详情页均出现
3. **字号档位真实存在**：详情页 59px 出现 405 次 = 正文标准字号
4. **图层组命名即结构规范**：详情页「图片×166 文案×166 元素×99」；
   主图「点击图×14 转化图×9」——**这直接对应设计任务类型**，
   且与 Eagle 文件夹结构（点击图-参考 / 转化图-卖点参考）**概念体系一致**，两个数据源可互相印证
5. **规格化程度极高**：SKU 画布 4480x6720、详情页 1440x29999（顶着 PS 高度上限做）

### 3.4 ⚠️ 实测发现的最大风险：新旧规范并存

抽样中的「其他」桶字体分布**完全不同**：SourceHanSansCN-Medium ×248、AdobeHeitiStd ×158，
几乎不含 MiSans；主色也从 #000000 变成 #070504。

这说明店铺存在**规范迭代**——老文件用思源黑体/Adobe 黑体，新文件改用 MiSans。
**若蒸馏不带时间维度，会把已废弃的旧规范和现行规范混成一锅，学出来的「规范」是错的。**
这直接对应用户需求里那句「获取**最新的**相关参考和知识」——时间维度不是可选项，是需求本身。

## 四、三个真断点

### 断点 1：候选区是终点站，不是中转站

`decideDesignLearningCandidate` 只在 ledger 里把 status 改成 `'promoted'`
（`design-workshop/design-learning.store.ts:82`）。**全仓没有任何代码把 promoted 候选
写进 `designMemoryItems` 或知识层**——晋升后唯一作用是在 `evaluateDesign` 里排序靠前。

学到的东西升不上去，知识库永远长不大。

### 断点 2：没有批量入口

- `analyzePsdDesignSource` 一次一份，且 P0 边界 B4 明确「不落盘」（profile 只作工具结果返回）
- `studyReference` 一次一张
- 学习运行时 `maxReferences` 上限 30、默认 8；PSD 侧 `DESIGN_LEARNING_PSD_SOURCE_LIMIT = 6`

**这是「每次学几条」的涓流设计。** 1025 份 PSD 靠模型逐个调工具永远跑不完。

### 断点 3：存储装不下，且跨项目不共享

- 设计记忆存 **localStorage**（`memory.service.ts:882/951`），`MAX_DESIGN_MEMORY_ITEMS = 2000`
- 学习候选区存**项目级** `.designecho/learning-candidates.json`
- 两套存储不互通；localStorage 装不下语料级知识（尤其 `learnedInsights` 明细）
- A 店学到的东西 B 店用不上——与「可复用」的需求直接冲突

### 附带缺口：Eagle 视觉分析目前是空的

`EagleVisualCaseAnalysisPlaceholder` 的 `ocrStatus`/`compositionStatus` 全为 `'unknown'`，
`subjectRegions: never[]`。元数据索引建好了，**视觉理解为零**。

## 五、必须正视的前提：不能交给模型自己记

记忆档案数据：472 份运行档案里记忆 update 仅 9%（08-10 后降到 5%）。
**「让模型在设计过程中顺手把知识记下来」这条路已被真机证伪。**

所以批量蒸馏必须走 **Harness 确定性管线**（服务/脚本定时跑），
模型只负责 L2 的判断部分和消费端。这与仓库既有判据一致：
有唯一答案的事（字号是多少、用了什么字体）交确定性代码，
没有唯一答案的事（这个版式好在哪）才交模型。

## 六、方案：按成本分三层

| 层 | 内容 | 成本 | 覆盖 | 依赖 |
|---|---|---|---|---|
| **L0 零模型** | PSD 结构：字号档位/色板/字体/版心/分屏节奏/组名规范 | ~1 小时全量 | 1025 份 | 无 |
| **L0b 零模型** | Eagle 元数据 + 616 个字体的字族气质 | 秒级 | 2529 条 | 无 |
| **L1 本地计算** | 图像主色/尺寸/构图分区/主体框 | 秒级/张 | 1701 张 | 本地 ONNX（已有 BiRefNet/SAM） |
| **L2 视觉模型** | `studyReference` 说得出好在哪、怎么做的 | 60–80s/张 | 参考文件夹几十张 | 视觉模型 |

**L0 是最高性价比的**：它恰好是最不依赖视觉模型、而设计规范含金量最高的部分——
客户的字号体系、色板、版心、命名规范本来就藏在 PSD 里，而且 §3.3 已实证它高度收敛。

### 6.2 深度维度：每层内部都要走完三步

成本分层（L0/L1/L2）是**取哪些原料**；深度分层（§1.2 的①②③）是**炼到什么程度**。
两者正交，不能混为一谈——L0 如果只做到①，跑得再快也只是把 PSD 换了个格式存。

L0 内部必须拆成三步，中间那步是初版漏掉的核心：

| 步 | 动作 | 产物 | 是否蒸馏 |
|---|---|---|---|
| **L0-a 提取** | 读 PSD → 字号/色板/字体/坐标/组名 | 逐文件档案 | ❌ 这是转码 |
| **L0-b 归一** | 尺寸除以画布宽 → 比例；字号聚成层级倍率 | 跨品类可比的关系 | ⭕ 半成品 |
| **L0-c 提纯** | 按 mtime 加权丢弃废弃规范；只留反复出现的 | 每店一页纸 | ✅ 蒸馏产物 |

**L0-c 的「丢」是蒸馏的核心动作，不是收尾。** 丢得对不对，决定产物是精华还是残渣。

成本不变（仍是零模型、约 1 小时），但产出的性质完全不同：
从「这店用过什么」变成「这店怎么做」。

## 七、L0 落地方案（已拍板方向）

### 7.1 存储：用户级全局知识库

> **归属见 §11**：本节按「独立新库」写就，归位到现有知识库后应改为
> 「知识库多一个来源类型」，共用其搜索/筛选/审核流程，不另起一套。

从 localStorage 迁到文件层。建议 `<userData>/knowledge/design-source/`：

```
design-source/
  index.json              # 蒸馏批次、覆盖范围、时间戳
  shops/<shop-id>.json    # 蒸馏产物：每店一页纸，存【关系】不存数值
  files.jsonl             # 备查残渣：每份 PSD 一行原始档案，不进模型上下文
```

**两者性质不同，别混为一谈**：`files.jsonl` 是 L0-a 的中间产物，作用是可追溯、
可在改聚合口径时不重读 665GB——它**不是知识库内容，不进模型上下文**。
真正被召回、被 Agent 使用的只有 `shops/<shop-id>.json`。

该文件存的是**关系**不是数值，形如：

```
字号层级: 标题 = 正文 × 2.2；正文 ≈ 画布宽 4.1%（跨 3 品类一致）
版心    : 详情页左边距 20.2% 画布宽；主图 5.1%
色板    : 主色 #000000（正文）／品牌绿 #A7CC66（点缀，主图与详情页共用）
字体    : 现行 MiSans 家族（Demibold 标题 / Regular 正文）；已废弃 思源黑体·AdobeHeiti
结构    : 详情页严格「一图配一文」（图片:文案 = 1:1，166 组样本）
```

理由：JSONL 追加成本恒定、可人工审阅、可 diff；聚合层单独存，改聚合口径不必重读 665GB。

**跨品牌污染防线**：每条知识必须带 `shopId` + `sourceFile` + `mtime`。
全局库只是存储位置全局，检索时按当前项目的店铺优先、跨店知识需显式标注来源。

### 7.2 时间维度：断层检测，不是拍衰减系数（应对 §3.4 风险）

**不问用户「规范多久变一次」，从数据里读。** 按 mtime 排序找字体/色板的**突变点**：
断层之后为现行，之前存为 `superseded`。比任何固定衰减参数都准，因为它是从真实文件里读出来的。
**断层本身就是一条知识**——「这店在某时间点把字体从思源黑体换成 MiSans」，
Agent 拿到老文件时能认出来。§3.4 实测的「其他」桶字体分布异常，就是这样一个断层。


聚合时按文件 mtime 加权：近 6 个月的文件权重 1.0，6–18 个月 0.5，更早 0.2。
输出规范时同时给出「现行」与「已废弃」两组，让 Agent 知道 MiSans 是现行、思源黑体是历史。

### 7.3 分类维度（实测踩过的坑）

**按文件名分类，不是按目录名。** 实测发现 PSD 全部集中在 `PSD/` 目录下，
文件名才是类型标签（`1200.psb` / `750.psb` / `800.psb` / `SKU.psb` / `详情页.psb`）；
`主图/` 目录里是导出的 jpg/png 成品，`模板文件/` 是 .tif（解析器按 B2 边界拒绝）。
分类维度搞错会漏掉绝大部分语料——本次首跑主图/SKU 桶抽样为 0 就是这个原因。

### 7.4 断点修复顺序

1. **存储层**：新建用户级知识库服务（文件落盘，非 localStorage）
2. **批量管线**：`distill:psd` 脚本/服务——遍历店铺 → 解析（L0-a）→ 逐文件档案入 JSONL
   → **归一成比例与倍率（L0-b）** → **按 mtime 加权提纯（L0-c）** → 出每店一页纸
3. **晋升通路**：把 promoted 候选真正写进知识库（补上断点 1）
4. **召回接线**：`searchDesignKnowledge` 的合并侧加读全局知识库
5. 之后再谈 L1/L2

### 7.5 边界（沿用 PSD P0 已定的约束，不放宽）

- B1 学模式不学内容：文字只留 ≤30 字样本，不读像素，不复制图片
- B2 只收 .psd/.psb；.tif 拒绝
- B3 ≤2GB（47 份超限文件如实记为 skipped，不静默丢弃）
- B7 诚实降级：读不到的字段进 warnings，不臆造

|---|---|---|---|
| `design-quality-assertion.ts` 断言评分 | 事后 | 这张图达标没 | ✅ 已有 |
| `design-workshop/design-evaluator.ts` 评审器 | 事后 | 这张图好不好看 | ✅ 已有 |
| critic 队友裁决 | 事后 | 产物能不能过 | ✅ 已有 |
| **假设** | 事前 | 我以为的规律成不成立 | ❌ 无 |
| **反问** | 事中 | 我凭什么这么以为 | ❌ 无 |

蒸馏产出的是**认知**（规律、规范），不是产物。评审器判不了「MiSans 是这店现行字体」这个命题对不对。

### 9.2 什么算一条假设

每条蒸馏结论都是假设，不是事实。必须带三样东西：

```
❌ 事实陈述          "MiSans-Demibold 占 71%"

✅ 假设
   命题    : 这店现行标题字体是 MiSans-Demibold
   证据    : 14 份文件 / 692 次 / 跨主图·详情页两品类
   反例    : 3 份文件用 AdobeHeitiStd（均为 2025 年前）
   证伪条件: 若最近 3 个月新文件中出现其他字体主导，本条作废
```

**没有证伪条件的不是假设，是信念。** 信念进知识库就成了不会自我纠正的偏见。

### 9.3 五个反问（四个零成本）

| 反问 | 问什么 | 执行者 | 成本 |
|---|---|---|---|
| **反例问** | 有没有反例？占比多少？ | 确定性 | 零 |
| **时间问** | 最近的文件里还成立吗？ | 确定性 | 零 |
| **样本问** | 来自几个**不同源文件**？ | 确定性 | 零 |
| **迁移问** | 换品类/画布还成立吗？ | 确定性（归一后比对） | 零 |
| **因果问** | 是设计决策，还是外部约束？ | **全自动三级判定（见下）** | 极低 |

**因果问最容易跳过、代价最大。** 主图 1500x2000、SKU 800x800 若不问因果，会被蒸馏成
「这店偏爱这些尺寸」的品味结论——但 800x800 极可能是电商平台硬性规定。
**把约束当品味学，Agent 会在不需要的场合去满足一个不存在的偏好。**
同理某个字号可能只是 PS 默认值、某个组名可能是模板自带。
品味 / 平台约束 / 工具默认在数据里长得一模一样，只有问「为什么是它」才分得开。

判据：**这个反问的答案能不能改变假设的去留？** 不能，它就是装饰。
（同源于 CLAUDE.md 的「它拦的是做错还是说错」。）

**因果问不问人，三级自动判定**（2026-08-19 用户拍板：蒸馏过程完全自动，不得打断用户）：

| 级 | 判据 | 怎么判 | 成本 |
|---|---|---|---|
| **1 跨源普遍性** | 这特征在别的店铺/竞品也出现吗 | 确定性比对 | 零 |
| **2 公共知识** | 800x800 是电商主图标准规格 | 模型**批量**判（一次一批，非一条一次） | 极低 |
| **3 判不了** | 证据不足以区分 | 标 `unknown` **照常入库** | 零 |

第 1 级最强且全自动：**到处都是的是约束，只此一家的才是品味**。当前只有单店语料时这条较弱，
随蒸馏覆盖更多店铺会自动变强；Eagle 库 2529 条（含大量竞品截图）本就是现成的外部对照组。

**unknown 必须放行，不能拦。** 三态与 CLAUDE.md 能力判定红线同构：
confirmed（品味）→ 用；refuted（平台约束）→ 也用，只是知道它是规则不是偏好；
**unknown（判不了）→ 放行并标注**。把 unknown 塞进复核队列等于「不确定就阻断」，
正是项目明令禁止、且已付出过代价的模式（模型能力未声明→判不支持→用户选得到却用不了）。

**不确定不等于不能用**：它该体现在**用的时候说明**（Agent 在设计说明里点出
「按你店一贯的 800x800 做了，不确定这是平台要求还是你们的习惯」），而不是拦在门口。


### 9.4 不建平行系统：接到现有候选区上

现有 `DesignLearningCandidate` 的晋升判据只有 `support`（出现次数）+ 人工点头。
次数多 ≠ 成立——一份文件里重复 100 次，`support` 就是 100，但源文件数是 1。

```
候选（现有结构扩展）→ 补 证据/反例/证伪条件
                    → 四问自动跑（零成本，确定性代码）
                    → 因果问（只对通过前四问的跑）
                    → confirmed / refuted / constraint_not_taste
                    → 晋升进知识库
```

### 9.5 真实事故佐证

记忆档案：Agent 把 PSD 旧稿的「防滑硅胶」抄成了中筒袜卖点。
那就是没有反问的后果——拿到一个假设（这产品卖点是防滑硅胶），没问证据是什么，直接当事实用。

项目已针对文案打过单点补丁（「功能词须有产品事实来源」）。假设-反问是把它上升为通用纪律：
**任何 Agent 要当成事实来用的东西，都得说得出证据和证伪条件。**

### 9.6 两个尚未想清的问题

1. ~~**反问由谁发起**~~ **（已决）**：靠模型自觉不成立（472 档案记忆写入率 9% 已证伪元认知自觉）。
   四问由 Harness 强制跑；因果问走 §9.3 三级自动判定。**「反问」在蒸馏管线里是代码，不是 Agent 能力，且全程不打断用户。**
2. **设计时的反问会不会成拖累**：蒸馏离线，慢无所谓；设计过程每个判断都反问会重演 0/49 门禁事故。
   倾向区分：**写入前的事实性断言**（卖点、尺寸、颜色来源）必须反问；**审美判断**不反问，交评审器事后验。
   **先只做蒸馏侧（离线、无风险），设计侧等蒸馏跑通再说。**

## 十、自动化：蒸馏不该是开关

### 10.1 现状：藏在设置最深处的手动按钮

- UI 标题字面就是「手动学习」，方法名 `runManual`（`DesignLearningRuntimeSettingsPanel.tsx:19`）
- 唯一入口是设置弹窗（`SettingsModal.tsx:2219`）
- 契约层**其实定义了自动触发源** `'app_start' | 'scheduled_timer' | 'manual'`，
  cadence 默认值还是 `'daily'`（`design-learning-cadence-scheduler.ts:153`）
- **但 `app_start` 与 `scheduled_timer` 在 renderer 里零调用点**

**不是设计成手动的，是本来就想做成自动的、只是没接线。** 这解释了记忆档案里
「Agent 没知识」三根因之一的「没点过学习」。

### 10.2 该自动的理由

用户需求原话是「获取**最新的**相关参考和知识」——「最新」本身就排除了手动。
手动必然滞后于素材变化，且靠人记得点已有反证（记忆写入率 9%）。

### 10.3 触发时机与执行策略

**触发（事件驱动，不是定时全扫）**
- 打开某店铺项目 → 无蒸馏档案 → 排队
- 文件 mtime 变化 → 增量排队
- 应用空闲（没在对话、PS 没在执行）→ 消费队列

**成本结构决定可行性**
- 首轮：665GB / 约 1 小时（一次性）
- 之后：**秒级**——mtime 判断零成本，一店一天改 3–5 个文件

**自动的真实代价只有首轮那一次。**

### 10.4 关键：一页纸测试是自动化的硬前提

产物小到一页纸 → 才能在打开项目时直接注入系统提示 → Agent 不需要「记得去查」。

反之若产出几千条数值，就只能建索引等检索，而检索必须由模型主动发起——又回到「靠自觉」的死路。
**产物形态与召回方式是绑死的，不是各自独立的品味问题。**
现成样板：主循环开始时自动注入 Design Project State 摘要，蒸馏产物应走同一条路，
而不是新开一个需模型主动调用的工具。

### 10.5 自动与人工的分界（由 §9 反问提供）

现设计把所有学习产物一律塞进 `needs_review`。一视同仁会出事：
用户要复核成千条「MiSans 出现 692 次」，必然放弃 → 队列积压 → 全部卡死。

| 类型 | 例子 | 处置 |
|---|---|---|
| 确定性事实，四问全过 | 字号档位、色板、字体、版心比例 | **自动入库** |
| 因果问 unknown | 800x800 是品味还是平台规定 | **标注后自动入库**，用时说明（不进队列，见 §9.3） |
| 模型判断类（L2） | 「这个设计好在哪」 | **必须复核** |

### 10.6 开关要不要

要，但**默认必须是开的**。问题从来不是「有没有开关」，是「默认值是什么」。
唯一需用户知情的是首轮 1 小时：告知 + 自动开始 + 可暂停——这是知情权，不是开关。

## 十一、归属：蒸馏归知识库，不归设置

### 11.1 容器早已建好

`KnowledgeLibraryPage.tsx`（985 行）已分三段，每块都有位置接住蒸馏：

| 知识库现有分区 | 描述 | 蒸馏放什么 |
|---|---|---|
| **知识总览** | 「从素材到设计判断」 | 蒸馏覆盖率、进度、触发入口 |
| **可用知识** | 搜索并加入任务 | 每店一页纸 |
| **待我审核** | 「你的知识收件箱」 | 只放因果问存疑的条目 |

来源筛选已有 `长期知识 / 内置方法论 / Eagle 参考 / Web 来源 / 已剔除`，
**唯独缺「设计源（PSD）」**——蒸馏产物正好填进这个精确缺口。

### 11.2 归位动作（不新建容器）

1. `SOURCE_FILTERS` 加一类 `design_source`
2. 蒸馏触发从设置弹窗挪到「知识总览」
3. 产物写进知识库，共用现有搜索/筛选/审核/剔除流程

### 11.3 入口位置就是产品语义

放在设置弹窗里，用户读到的是「配置项」——心智是设一次就不用管，所以没人会天天进设置去点。
放在知识库里，读到的是「我的资产」——会去看、会关心它长没长。
同一功能挪个位置，用户预期完全不同。这不是 UI 美化，是**功能定位纠正**。
知识库页面自己的文案已说明白：「这里不是 AI 自动学习开关，而是你的知识收件箱」。

### 11.4 一个不建议动的命名债

产物现存进 `designMemoryItems`（**记忆**），但知识库页面把它当「长期知识」展示。概念确实错位：
记忆 = 情景性（上次用户说不喜欢这配色）；知识 = 规律性（这店标题字体是什么）。

**不建议为此改名**——纯重构、收益低风险高。真正要动的是**存储位置**：
从 localStorage（2000 条上限）挪到文件层，那才是拦住语料级蒸馏的实际瓶颈。

### 11.5 对 §7.1 的修正

§7.1 原按**独立新库**设计。归位后应改为：**知识库多一个来源类型**，
共用现有流程，而不是另起一套（CLAUDE.md 明确反对平行逻辑）。
