# 设计 Agent + Harness 系统蓝图（2026-08-18）

> **状态：历史工作稿，已由 2026-08-21 边界裁决取代。** 当前真相源是 `project-memory/Prompt.md` 与 `docs/design-agent-operating-system.md`。本文保留 2026-08-18 的问题背景和路线线索；其中“七步固定常驻”“任务卡覆盖每个任务”“出稿必评”“候选可被生产消费”“工具面运行中保持不变”等旧主张不再生效。

用户与 Claude 当天讨论的系统化整理：目标、边界、Agent 内核、Harness 六层、数据层、学习闭环、效率、最小目标与验收、路线。它不再是后续会话的总纲；冲突时一律以当前 A 层真相源和代码为准。

## 0. 一句话
**做一个会设计的 Agent（判断、创意、取舍）+ 让它能把设计做成、做好、做快的 Harness（工具、证据、记忆、评估、护栏、编排）+ 装知识与品味的数据层（品类知识、Skill、配方、素材、规范、校准样本）+ 一条让它越做越好的学习闭环。** 不做品类机器，不做预设模板，不打地鼠。

## 1. 目标与验收（用户口径）

| 目标 | 含义 | 验收方式 |
|---|---|---|
| ① 说得出为什么 | 理解与创意：每张稿有设计说明（目的 / 主张 / 结构 / 视觉 / 文案来源） | 设计说明必填且与成稿一致（评审器对照） |
| ② 判断好不好看 | 审美与知识：先判对不对（事实、几何），再判好不好看（四标准） | 评审器与用户判断一致率 ≥ 80%（用户 5 好 5 差样本校准） |
| ③ 自己规划、会组织 | 经验与执行：任务卡（角色与为什么 / 判断 / 清单）→ 逐项带收据打勾 → 清单达成才算完成 | 任务卡覆盖每次设计任务；完成不再靠自报 |
| ④ 什么都能做 | 主图 / SKU / 详情页之外：明信片、海报、包装、品牌全案… | 内核零品类词；印刷 / 多页 / 刀版能力齐 |
| ⑤ 做得好 | 不只是能做 | 画廊平均分 ≥ 6.5 → 8；同 brief 三轮内 pass |
| ⑥ 高效 | 少调用、少时间、少带图 | 单张主图 ≤ 3 次模型调用 ≤ 2 分钟；SKU 一套 ≤ 5 分钟；详情页 ≤ 1 分钟 / 屏 |
| ⑦ 自我提高 | 设计在变，Agent 不能是死的 | 学习候选区每周有转正；画廊曲线向上 |

## 2. 边界（行业定义，三问判据）
- **Agent**：模型 + 循环 —— 判断、创意、取舍。
- **Harness**：工具 / ACI、观察与证据、记忆与上下文、评估与验证、权限护栏、编排 —— 能力、精度、底线。
- **数据层**：品类知识、Skill、配方、素材、规范、校准样本 —— 由 Agent 选用。
- **三问**：是不是在替 Agent 做判断？是不是它缺的一条能力或证据？换成海报 / 详情页还成立吗？过不了不动代码。
- **修手 ≠ 打地鼠**：真实 bug（读回误判、写入身份泄漏、死循环）要修，但修完回到能力建设。

## 3. Agent 内核（底层思维，无品类词）
1. **七步工作法**：目的 → 内容 → 材料 → 结构 → 视觉语言 → 制作 → 看与修。它是 Design Kernel 可按需取用的思考脚手架，不是 Harness 固定阶段，也不常驻完整 System Prompt。
2. **任务卡**：复杂、多产物或需要显式恢复的任务可由模型选用；Harness 只记录其状态。简单局部编辑和清晰的单步任务不强制建卡。
3. **设计说明**：每次动手前说得出为什么（已落地，composeDesign 必填）。
4. **选图判断**：按目标从项目摄影图里选对那张并说明理由（主体清、留白够、气质对、真实性）。
5. **构图判断**：起手式配方或自己划格；两条主体处理路径（摄影满幅 / 抠图合成）由目标决定。
6. **看参考**：带目的找 → 说得出好坏 → 推演做法 → 好的沉淀差的改进（studyReference，已落地）。
7. **文案思维**：目的 → 一个主张 → 事实支撑（产品事实先于文案）→ 语气 → 长度 → 来源；**契约按用户的判断顺序建（待用户给）**。
8. **看与修**：按交付风险选择结构读回、画面复核或独立评价；不无限微调。开放首稿不因缺少自动评审而禁止写入或自然交付。
9. **发现问题**：先判对不对（文案与本品、模板来源、占位是否填、几何硬项），再判好不好看。

## 4. Harness 六层：现状与缺口

| 层 | 已有 | 缺口（按优先级） |
|---|---|---|
| **工具 / 引擎（粒度对、确定性归代码）** | composeDesign（一次成稿、自由构图、摄影优先 / 抠图合成）、renderLayout、主体感知缩放、放多大放哪几何、SKU 排版执行器、createDocument 支持 dpi / 色彩模式 | 字体气质与图层样式、点缀元素、抠图只取产品；SKU 色卡契约与模板结构报告；确定性建模板；多页 / 多画板；印刷检查；刀版证据 |
| **观察与证据（看得到、算得准）** | 主体框（素材属性）、素材理解、运行事实账本、导出图贴回对话、开场只认文档身份 | 模板结构报告；素材库背景 / 元素供给（Eagle）接进选图；文本层内容读取进核对器（已在 SKU 备注） |
| **记忆与上下文** | 项目状态、事实账本、续跑摘要、提示体量账本、任务卡跨轮 | 店铺级记忆；轮内语义摘要 |
| **评估与验证** | evaluateDesign 四标准 + 硬项、对不对核对器、画廊评测、完成契约绑定任务卡 | 用户校准样本；强视觉模型；印刷检查硬项；效率指标进画廊 |
| **权限与护栏** | 破坏性动作 hook、只读来源文档、Skill 写入声明 | 只减不增；不再加前置流程门禁 |
| **编排** | 生成器 / 评审器分离；工作流交回熔断；写入身份释放 | Skill 执行器交出判断（SKU 样板）；子代理只在超出单模型能力时用 |

## 5. 数据层
- 品类知识（主图 / 详情页 / SKU 方法论）只作 Agent 可取用的知识，不进内核。
- Skill：用户可建；执行器只做确定性部分。
- 版面起手式由 Agent 根据当前目标、素材和参考临时声明；Harness 不维护内置审美配方。
- 素材：项目摄影图为主；Eagle 背景 / 元素 / 参考；成稿 PSD → 规范档案。
- 校准样本：用户的好 / 差样本与留 / 改 / 弃原话。

## 6. 学习闭环（借鉴 HermesAgent）
运行案例可形成候选，但候选不直接进入生产。当前已接通两条受控出口：用户明确“留 / 改 / 弃 + 原因”可发布为项目 Evaluation 校准；参考图解读进入长期 Memory 人工审核队列，批准后才可检索。模型评审只形成 finding，不能自我转正为原则、配方、Skill 或 Policy；跨项目发布仍需独立离线评测、版本与回滚。

## 7. 效率（主要归 Harness）
动作粒度、确定性归引擎、证据前置、并行与预算、上下文体量、稳定工具面 —— Harness；少而准的决策 —— Agent；带图回合速度 —— 模型。效率指标进画廊（调用数 / 秒数 / 带图回合），分数不降时间下降才算改进。

## 8. 最小目标（先做好三样）
- **M1 主图**：画廊 10 条真实 brief（摄影优先）；评审校准；工艺三件（字体气质 / 主体尺度 / 抠图只取产品）→ 平均分 ≥ 6.5、三轮内 pass。
- **M2 SKU**：三处不稳变证据（色卡契约预检、模板结构报告）→ 判断归位（模板合不合适 / 组合 / 文案 / 选图交 Agent）→ 确定性建模板 → 中期并入车间"多主体网格"让占位符退为可选 → 一套 13 张、备注文案本品化 0 违例、评审 ≥ 6.5。
- **M3 详情页**：逐屏车间 + 屏间一致（同色板同字体刻度）+ 逐屏评审 + 长图导出；不再有空占位 / 黑块。

## 9. 「什么都能做」的能力清单（Harness 侧，非流程）
画布规格换算（mm / dpi / 出血 / CMYK，已做）→ 多页 / 多画板 → 印刷检查硬项 → 包装刀版 / 展开图证据 → 字体来源与嵌入 → 品牌系统（同一套色板 / 字体刻度跨物料复用）。

## 10. 不做什么
不为单次失败加门禁；不写品类流程进 Agent；不用"默认"替设计师定风格；不把配方当模板；不拿 smoke 假绿当验收；不承诺一次就惊艳；生成式只作元素辅助不作主画面。

## 11. 需要用户提供的（比代码更决定"像不像你"）
5 好 5 差样本各一句为什么；文案的判断顺序；字体库与常用元素在哪；Eagle 里背景 / 元素分类；每张成稿一句留 / 改 / 弃；视觉模型槽换强模型（或 OpenRouter 充值）。

## 12. 路线（顺序即优先级）
M2 前置证据（色卡契约、模板结构报告）→ M1 画廊扩容 + 评审校准 → 判断归位（SKU 样板）→ 工艺三件 → M3 详情页逐屏 → 什么都能做的能力清单 → 反思器 / 自写 skill。每一刀先过三问，用画廊分数与效率指标说话。
