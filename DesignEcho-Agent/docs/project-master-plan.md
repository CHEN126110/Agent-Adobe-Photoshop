# DesignEcho 分阶段 SMART 项目路线

> 文档类型：B 层长期路线与阶段验收辅助。
> 当前开发权限：不能直接决定当前改动；当前唯一顺序以 `project-memory/Plan.md` 为准。
> 适用范围：从文档治理、技术可靠交付、设计认知、业务 Skill、商业质量到效率与受审学习。
> 不能覆盖：`project-memory/Prompt.md` 的产品边界、`CurrentTask.md` 的本轮范围、Design Agent OS、当前代码和真实运行读回。

更新日期：2026-08-31

## 1. 路线目的

项目不再用“让 Agent 更聪明”“把 Harness 做好”“最终像专业设计师”这类无法验收的句子直接驱动开发。长期方向保持不变，但实现必须拆成有顺序、可证伪、可停止的阶段。

本路线把用户目标分为两层：

1. **低预期**：现有主图、SKU、详情页 Skill 能稳定理解自然需求，正确使用真实素材，在 Photoshop 中生成可编辑源稿与同版本导出，并达到用户成稿和 Eagle 参考的可用水平。
2. **高预期**：同一 Agent 不依赖业务 Skill，也能像成熟设计师一样理解画面、形成创意方向、处理构图 /层级 /排版 /色彩 /工艺、说明关键取舍、完成有界修订，并在质量不下降的前提下快速交付。

高预期不能跳过低预期，也不能用更多 Prompt、更多角色、更多固定流程或换模型代替真实验收。

## 2. SMART 与状态规则

每个阶段固定回答以下问题：

- **Specific**：最终要出现什么用户可观察结果。
- **Measurable**：使用哪些固定样本和指标，目标值是多少。
- **Achievable**：依赖哪些当前已存在能力，哪些前置必须先闭合。
- **Relevant**：它解决四项北极星中的哪一项。
- **Time-bound**：激活后的时间盒，以及到期后如何裁决。
- **Exit / Stop**：达到什么条件才能进入下一阶段，什么情况必须停下来 GMR。

状态词只使用：

- `planned`：已定义但未激活；
- `active`：当前唯一主阶段；
- `validated`：达到本阶段全部退出条件；
- `blocked`：存在明确外部或授权阻塞；
- `failed_gmr_required`：时间盒结束或重复失配，需要 GMR，不能自动顺延；
- `superseded`：被新的同 owner 目标明确取代。

一个阶段的 `validated` 只证明它自己的范围。技术通过不能外推设计质量，设计盲评通过不能外推所有品类，单次成功不能外推稳定性。

## 3. 统一指标字典

### 3.1 技术成功

一次任务同时满足以下条件才计技术成功：

1. 正确 TaskRun、正确 Photoshop 文档和正确 revision；
2. 所需 mutation 真实提交，没有写到外部文档；
3. 同目标写后读回成立；
4. 必需 PSD / PSB 与导出图齐全且绑定同一成品版本；
5. 没有伪完成、未知写状态或未结算的弃稿文档；
6. 用户没有代替 Agent 操作 Tool 或修复文件。

### 3.2 设计质量

设计质量与技术成功独立记录，至少包含：

- 商品 /内容事实正确；
- 素材角色与选图合理；
- 主体裁切、尺度与清晰度；
- 构图、视觉重心、留白和图文关系；
- 信息层级、排版和缩略图可读性；
- 色彩、材质、背景与合成协调；
- 可编辑图层结构；
- 与用户成稿 / Eagle 参考的匿名成对偏好。

自动 Evaluation 只提供 finding。稳定商业质量必须由人工盲评或成对比较校准。

### 3.3 人工介入

下列情况计人工介入：

- 用户替 Agent 点击 Photoshop、选择 Tool、修改图层或修复输出；
- Agent 重复询问本可观察的环境事实；
- 同一个已经回答的决定再次打断用户；
- 用户必须用开发术语解释下一步 Tool 或恢复路线。

用户独占的商品事实、品牌取舍、版权 /合规授权和不可逆批准不计无效介入。

### 3.4 效率

只有质量基线稳定后才优化：

- 任务总时长 p50 / p90；
- 首个有效设计版本时间；
- 模型调用和真实 input token；
- Tool 调用、重复观察和连续 transform 次数；
- 每个技术成功、人工可用结果的成本。

减少必要看图、写后复核或真实 Photoshop 读回来换速度，视为质量退化，不计优化。

## 4. S0 文档真相源恢复

状态：`validated`

时间盒：激活后 1–2 个工作日。

### Specific

当前任务、当前计划、当前状态、机器投影和长期路线各归唯一 owner；早期开发稿不能再作为默认实现指令。

### Measurable

- `CurrentTask.md` 恰好 1 个 H2；
- `Plan.md` 恰好 1 个 H2；
- CurrentTask、Plan、`activeRequest.id`、`activePlan.id` 四者一致；
- `Status.md` 只保留当前能力、当前样本和当前未知；
- A/B 层当前文档不引用不存在的 `npm run` 命令；
- 高干扰历史文档声明文档类型、当前权限、适用范围和上位真相源；
- 规划检查零 warning，并能对人为 ID 漂移失败。

### Achievable

项目已有 Git 历史、文档治理和维护检查；本阶段不需要改变生产 Runtime。

### Relevant

消除旧目标、旧模型结构和旧验证命令对后续工程 Agent 的错误约束，提高研发证据效率。

### Exit / Stop

全部指标通过后进入 S1。无法判断某份专业资料是否仍有消费者时，先降为 C/D 层并保留，不为追求文件数量盲删。

## 5. S1 技术可靠交付基线

状态：`planned`

时间盒：激活后 10 个工作日。

### Specific

在不评价审美上限的前提下，使 Agent 能在复杂 Photoshop 环境中正确选择自己的任务文档、完成 mutation、读回、保存和导出，并诚实处理失败。

### Measurable

- 冻结 5 个未见真实 Case，至少覆盖：空白新建、已有可编辑文档、外部 dirty 文档在场、可恢复失败、真实停止；
- 同一代码、模型、reasoning、素材、预算和 Case 各运行 2 次，共 10 次；
- 技术成功率至少 8 / 10；
- 外部文档误写、误保存、误关闭为 0；
- 错误完成声明为 0；
- 每个失败都能落到唯一 owner 和首个偏差；
- INTAKE-083 / 084 的重复 blocker 在购买下一轮正式样本前先闭合或被新证据证伪。

### Achievable

现有 TaskRun、目标 / revision、事务、读回、Artifact 和 Reliability 基础已能产生真实证据；主要工作是关闭重复交付与评审断点，而不是重建 Runtime。

### Relevant

直接提高真实成功率并降低人工救火，是后续设计质量评测可信的前提。

### Exit / Stop

达到 8 / 10 且零跨文档事故后进入 S2。若同一 blocker 在两轮不同修复后重复，立即 GMR；不得通过放宽收据或减少 Case 制造通过。

## 6. S2 设计认知与首次构图

状态：`planned`

时间盒：激活后 15 个工作日。

### Specific

让同一多模态 Agent 面对摄影图时，先形成与当前任务绑定的视觉事实、设计机会和构图关系，再把自己的决定一次性映射到 Photoshop；Harness 不替它审美。

### Measurable

- 使用 5 个未见单画布 Case，每个 A / B 各运行 3 次；A 为当前链，B 只增加 Agent 作者化的 Design Perception Note / Composition Intent 与机械编译；
- 每次开放设计首写前都有简短、可检查的设计判断，说明主体、设计机会、图文关系和裁切保护；不展示私有思维链；
- 商品事实错误为 0；
- 明显关键主体误裁不超过 1 / 15；
- 选图角色正确率至少 12 / 15；
- B 组中位连续 corrective transform 不高于 1 次，并显著少于 A 组；
- 人工匿名成对比较中，B 组“更好或等效”至少 60%；
- 同一 Intent 重放 3 次的图框 /主体几何结果稳定在当前契约容差内。

### Achievable

模型已经偶发产生设计师式判断，现有图框几何也能精确执行；本阶段验证缺口是否主要来自视觉语义到执行参数的中间表达，而非凭假设大改工具层。

### Relevant

直接解决“Agent 像操作员而不像设计师”、选图重复、裁切错误和反复 transform。

### Exit / Stop

只有 B 组同时改善人工质量和调整次数才进入 S3。几何稳定但盲评不提高，根因转向模型判断 /参考 /评价校准；同一 Intent 重放不稳定，则先回到 Photoshop 执行层。

## 7. S3 三类业务 Skill 的低预期交付

状态：`planned`

时间盒：激活后 20 个工作日。

### Specific

让主图、SKU、详情页通过现有 Skill Package 与共享 Runtime 完成自然语言理解、真实素材、分层 Photoshop 制作、同版本交付和人工可用质量。

### Measurable

- 主图、SKU、详情页各 5 个未见 Case，共 15 个；
- 每类技术成功至少 4 / 5，总计至少 12 / 15；
- 商品 /规格 /颜色 /文案确定性错误为 0；
- 完成任务的可编辑源稿与导出同版本比例为 100%；
- 外部文档误操作为 0；
- 至少 10 / 15 被盲评为“可直接使用或只需一次局部修改”；
- 同一已回答卡片无进展重问为 0；
- 业务差异只存在 Skill Manifest、方法、卡片、规格和评价 overlay，不进入通用 Agent 分支。

### Achievable

三个 Skill、交互卡、Photoshop Tool 和业务契约均已有局部实现；S1 / S2 先提供可信执行与设计关系底座。

### Relevant

这是用户当前低预期，也是验证 Agent + Harness 是否真正能完成电商生产的第一组产品结果。

### Exit / Stop

任一品类低于 4 / 5 时不外推该品类稳定。某一 Skill 的特有问题留在该 Skill；共享失败回到 Runtime / Tool / Design Kernel，不能复制三套补丁。

## 8. S4 无 Skill 的专业泛化与商业质量

状态：`planned`

时间盒：激活后 30 个工作日。

### Specific

在禁用主图、SKU、详情页业务 Skill 的条件下，让 Agent 依靠模型知识、Design Kernel、通用 Tool、必要参考和经审核经验完成不同类型的单画布设计。

### Measurable

- 至少 10 个跨场景未见任务，包含海报、Banner、社媒封面、改版和图文构成；
- 不新增 Case /品类关键词分支；
- 至少 8 / 10 技术交付成功；
- 至少 7 / 10 被两名人工评审判为“可用或只需一次局部修改”；
- 与对应用户成稿 / Eagle 参考的匿名成对比较中，“等效或更好”至少 60%；
- 关键事实错误和不可编辑假交付为 0；
- Agent 的公开设计判断与最终成稿关系一致，不是事后合理化。

### Achievable

S2 已验证视觉认知与构图关系，S3 已验证真实生产和人工评价；本阶段只扩大任务分布，不建立新的通用 Runtime。

### Relevant

对应用户的高预期：Agent 不依赖固定 Skill，也能表现出成熟设计师的判断和适应性。

### Exit / Stop

达到目标后才能讨论“专业设计 Agent”阶段性成立。若结果只在袜子电商上有效，说明仍是业务过拟合，返回 Design Kernel /案例分布，而不是改名为通用能力。

## 9. S5 质量不退化的效率与受审学习

状态：`planned`

时间盒：激活后 15 个工作日建立首轮配对结果，之后按季度复核。

### Specific

在复用 S3 / S4 固定任务包的前提下，减少无效观察、模型调用、Tool 往返和重复调整，并把人工确认的经验安全沉淀。

### Measurable

- 技术成功率与人工质量相对基线下降不超过 5 个百分点；
- 任务 p50 总时长、模型调用、无效观察和重复 transform 至少两项下降 30%；
- 用户独占事实之外的平均人工打断不高于每任务 1 次；
- 只有具备终态 TaskRun、operation result、同目标 verification、DesignVerdict 和人工反馈的案例进入经验候选；
- 正式 Knowledge / Skill / Evaluation 变更全部具备人工批准、版本、Canary 和回滚点；在线 Agent 自动晋升次数为 0。

### Achievable

前四阶段提供同分布基线，现有 Runtime Accounting、Memory 审核和 Experience Publisher 可承载受控比较。

### Relevant

在“先做对、做好”之后实现用户期待的快速高效，同时不让性能优化再次削弱 Agent 能力。

### Exit / Stop

任何显著质量退化立即回滚对应优化。没有可比 usage 或样本时保持未知，不用估算值证明效率。

## 10. 阶段切换与 GMR

1. 只有 `project-memory/Plan.md` 能激活一个阶段；本文件的 `planned` 不等于正在开发。
2. 阶段退出时必须把技术、视觉、人工介入和效率分别记账，不能合成一个总成功分。
3. 同一验收项两轮实质不同实现仍同模式失败、时间盒结束仍没有缩小未知、或开始增加样例专属补丁 /第二 owner 时，状态改为 `failed_gmr_required`。
4. GMR 只重新裁决根因、owner、保留 /回滚和下一项最小实验，不借机扩张宏大架构。
5. 用户可以改变业务优先级；工程实现、测试与回滚方案仍由工程 Agent 依据当前代码和事实决定。

## 11. 不在路线中承诺

- 不承诺通过换更强模型自动修好 Harness。
- 不承诺一次性重写 v3 或新建第三 Runtime。
- 不承诺任何单次样本代表稳定商业质量。
- 不承诺自动学习、自动发布或无限自主电脑控制。
- 不承诺与 Eagle 参考像素级照抄；目标是满足同一商业目的并达到可比较的专业完成度。
- 不以文档存在、静态审计、Tool success、模型自评或文件生成冒充真实产品结果。
