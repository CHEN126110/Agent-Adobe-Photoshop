# Implement

## 定位

本文件是条件性执行参考，不是默认必读清单，也不得覆盖 `AGENTS.md`、当前用户指令、首张 `CurrentTask.md` 任务卡或当前代码事实。开发方法以 `../docs/agent-development-methodology.md` 的风险相称流程为准；只有任务确实需要实施交接、规划写回或跨模块复盘时才读取本文件。

## 开始与阅读

1. 默认只读取 `Prompt.md` 与 `CurrentTask.md` 的第一个 H2 当前任务卡；先检查当前代码、调用链、运行状态与用户目标。
2. 架构或文档权威变化时再读治理文档与 Design Agent OS；排期时读 `Plan.md`、`Intake.md`、`Backlog.md`；核对历史验证时读 `Status.md`；风险与历史方案按需读 `Risks.md`、`Decisions.md`。
3. 小而可逆的局部改动不要求先更新项目记忆。当前业务目标、实施边界或跨轮交接事实发生实质变化时，才更新首张 `CurrentTask.md` 卡。
4. 用户明确要求“加入规划、后续要做或不要遗忘”时写入 `Intake.md`；不要只在聊天中承诺，也不要把普通当前任务机械复制到所有规划文件。

## 事实、推断与未知

1. 必须区分已验证事实、合理推断、待验证假设和未知项，但不强制每句话套固定标签，也不向用户提交形式化“证据报告”。
2. 日志、构建、测试、真实 Host 读回和官方协议可支持相应范围的结论；缺少某类证据不自动等于失败，更不能补造结果或把单一 case 外推为通用能力。
3. 暂时无法验证时，缩小影响面、保留失败检测与回滚点，并如实写明仍未知的用户可见结果。

## 技术决策与实现

1. 用户决定业务目标、优先级、验收口径和不可接受结果；工程 Agent 检查现状后决定技术路线并继续推进，不把框架、状态模型、存储或重构选择题交回用户。
2. 优先修根因、收敛唯一 owner 和真相源；不通过吞错、默认成功、重复状态或第二套控制面掩盖问题。
3. 开放创意走 `agentic`，规格化生产走 `staged`；共同复用执行预检、稳定目标、事务 owner、必要读回和不可逆审批。
4. 调试、benchmark 与生产 Runtime 保持隔离。业务场景不能重新定义底层 Tool、权限或完成事实。

## 验证

验证与改动风险相称：

1. 检查直接相关代码和边界；能运行的最小相关类型检查、构建、现有审计或可复用功能测试应直接运行。
2. 涉及跨模块协议、持久化、权限、迁移、打包或真实 Host 时，补充相应集成验证和可回滚实验；用户可见主链仍未实测时必须明确保留为未知。
3. `npm run maintenance:validate` 是核心回归入口，不是所有文档修改的仪式门票。运行后若被无关脏工作树问题提前阻断，应如实记录该失败，并继续运行与本次改动相关的后续检查；不得改断言、吞错误或重写用户文件制造假绿。

## 写回

只更新事实发生变化的唯一 owner：当前任务写 `CurrentTask.md`，排期池写 `Intake.md` / `Backlog.md`，长期决定写 `Decisions.md`，共享验证日志写 `Status.md`。没有对应事实变化就不写；历史文档不因当前聊天被批量同步。

## 当前环境注意事项

1. 仓库存在多类未收口改动，不能随意重置、清理、覆盖或混合提交。
2. 源码与文档使用 UTF-8 无 BOM 和仓库规定的行尾；PowerShell 读取中文时显式指定 UTF-8。
3. 设计方向、协议可行性、构建通过、真实 Photoshop E2E 和稳定商业质量是不同层次的结论，必须分别陈述。
